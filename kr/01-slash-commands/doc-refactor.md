# 문서 리팩토링

프로젝트 유형에 맞게 문서 구조를 리팩토링합니다:

1. **프로젝트 분석**: 유형(라이브러리/API/웹 앱/CLI/마이크로서비스), 아키텍처, 사용자 페르소나 식별
2. **문서 중앙화**: 적절한 상호 참조와 함께 기술 문서를 `docs/`로 이동
3. **루트 README.md**: 개요, 퀵스타트, 모듈/컴포넌트 요약, 라이선스, 연락처 정보가 포함된 진입점으로 간소화
4. **컴포넌트 문서**: 설정 및 테스트 지침이 포함된 모듈/패키지/서비스 수준 README 파일 추가
5. **`docs/` 구성**을 관련 카테고리별로:
   - 아키텍처, API 참조, 데이터베이스, 디자인, 문제 해결, 배포, 기여 (프로젝트 요구사항에 맞게 조정)
6. **가이드 생성** (해당되는 것 선택):
   - 사용자 가이드: 애플리케이션을 위한 최종 사용자 문서
   - API 문서: API의 엔드포인트, 인증, 예제
   - 개발 가이드: 설정, 테스트, 기여 워크플로우
   - 배포 가이드: 서비스/앱을 위한 프로덕션 배포
7. 모든 다이어그램에 **Mermaid** 사용 (아키텍처, 흐름, 스키마)

문서를 간결하게 유지하고, 스캔하기 쉽게 하며, 프로젝트 유형에 맞게 문맥에 맞춥니다.
