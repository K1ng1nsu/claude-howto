# Planning Mode 예제

Claude Code에서 planning mode를 효과적으로 사용하는 실제 예제입니다.

## 예제 1: REST API 구축

### Planning Mode 없이

```
User: 블로그용 REST API를 만들어 주세요

Claude: API를 만들겠습니다...
[즉시 코딩 시작, 요구사항을 놓칠 수 있음]
```

### Planning Mode 사용

```
User: /plan 블로그용 REST API 구축

Claude: 블로그 API에 대한 포괄적인 계획을 세우겠습니다.

## 블로그 REST API 구현 계획

### 1단계: 프로젝트 설정 (15분)
1. Express로 Node.js 프로젝트 초기화
2. TypeScript 설정 구성
3. 의존성 설치 (express, pg, jwt, joi)
4. 환경 변수 구성
5. 프로젝트 구조 설정

### 2단계: 데이터베이스 레이어 (30분)
6. 데이터베이스 스키마 설계
   - users 테이블 (id, email, password_hash, created_at)
   - posts 테이블 (id, user_id, title, content, published, created_at, updated_at)
   - comments 테이블 (id, post_id, user_id, content, created_at)
7. 마이그레이션 파일 생성
8. 데이터베이스 연결 풀 설정
9. 데이터베이스 모델 구현

### 3단계: 인증 (45분)
10. 사용자 등록 엔드포인트 구현
11. JWT를 사용한 로그인 엔드포인트 구현
12. 인증 미들웨어 생성
13. bcrypt로 비밀번호 해싱 추가
14. 토큰 갱신 로직 구현

### 4단계: Posts API (40분)
15. GET /api/posts - 게시된 모든 글 목록 (페이지네이션 포함)
16. GET /api/posts/:id - 단일 글 조회
17. POST /api/posts - 새 글 작성 (인증 필요)
18. PUT /api/posts/:id - 글 수정 (인증 필요, 소유권 확인)
19. DELETE /api/posts/:id - 글 삭제 (인증 필요, 소유권 확인)
20. GET /api/users/:id/posts - 사용자의 글 조회

### 5단계: Comments API (30분)
21. GET /api/posts/:id/comments - 댓글 조회
22. POST /api/posts/:id/comments - 댓글 추가 (인증 필요)
23. DELETE /api/comments/:id - 댓글 삭제 (인증 필요, 소유권 확인)

### 6단계: 검증 및 오류 처리 (30분)
24. Joi로 요청 검증 추가
25. 전역 오류 처리기 구현
26. 입력 정화 추가
27. 속도 제한 구현

### 7단계: 테스트 (60분)
28. 모델 단위 테스트 작성
29. 인증 엔드포인트 통합 테스트 작성
30. posts 엔드포인트 통합 테스트 작성
31. comments 엔드포인트 통합 테스트 작성
32. 80%+ 코드 커버리지 달성

### 8단계: 문서화 및 배포 (30분)
33. Swagger로 API 문서 생성
34. 설정 지침이 포함된 README 생성
35. Docker 설정 추가
36. CI/CD 파이프라인 설정

**예상 시간**: 4.5시간
**생성할 파일**: ~25개
**주요 기술**: Express, PostgreSQL, JWT, TypeScript

**API 엔드포인트 요약**:
- 인증: 2개 엔드포인트
- Posts: 6개 엔드포인트
- Comments: 3개 엔드포인트
- 총: 11개 엔드포인트

계속 진행하시겠습니까? (yes/no/modify)

User: yes

Claude: 1단계: 프로젝트 설정 시작...
[각 단계를 체계적으로 구현]
```

## 예제 2: 데이터베이스 마이그레이션

```

Claude: 이것은 복잡한 마이그레이션입니다. 상세한 계획을 세우겠습니다.

6. 잠재적 마이그레이션 문제 식별

### 2단계: PostgreSQL 설정 (1일)
7. PostgreSQL 데이터베이스 설정
8. 테이블, 인덱스, 제약 조건이 있는 스키마 생성
9. 연결 풀링 설정
10. 백업 전략 구성

### 3단계: 이중 쓰기 구현 (2-3일)
11. 데이터베이스 추상화 레이어 생성
12. 두 데이터베이스에 이중 쓰기 구현
13. 데이터 일관성 검사 추가
14. 스테이징에 이중 쓰기 배포
15. 문제 모니터링

### 4단계: 데이터 마이그레이션 (4일)
16. MongoDB 데이터 내보내기 스크립트 생성
17. PostgreSQL 데이터 가져오기 스크립트 생성
18. 데이터 변환 로직 구현
19. 프로덕션 데이터 복사본으로 초기 마이그레이션 실행

### 5단계: 점진적 전환 (5-7일)
21. 프로덕션에서 이중 쓰기 활성화
22. 배치 단위로 기록 데이터 마이그레이션
23. 지속적으로 데이터 일관성 검증
24. 두 데이터베이스 모니터링
25. 데이터 동기화 문제 수정

### 6단계: PostgreSQL 기본 (8일)
26. 읽기 작업을 PostgreSQL로 전환
27. 쿼리 성능 모니터링
28. 느린 쿼리 최적화
29. 안전을 위해 이중 쓰기 계속

### 7단계: MongoDB 폐기 (9-10일)
30. MongoDB 쓰기 중단
31. 2주간 MongoDB를 백업으로 유지
32. 코드에서 MongoDB 의존성 제거
33. MongoDB 데이터 보관
34. MongoDB 인스턴스 폐기

**예상 시간**: 10일
**위험 수준**: 높음
**롤백 전략**: 이중 쓰기로 MongoDB 계속 실행
**성공 기준**:
- 데이터 손실 제로
- <5% 성능 저하
- 모든 테스트 통과

**주요 위험**:
1. 마이그레이션 중 데이터 불일치
2. 쿼리 성능 저하
3. 애플리케이션 다운타임
4. 데이터 손실

**완화 방안**:

- 점진적 전환

## 예제 3: 프론트엔드 리팩토링

```
User: /plan React 앱을 클래스 컴포넌트에서 hooks로 리팩토링

Claude: 체계적인 리팩토링 계획을 세우겠습니다.

## React Class to Hooks 마이그레이션 계획

### 1단계: 준비 및 분석 (2시간)
1. 모든 클래스 컴포넌트 감사 (모든 .jsx/.tsx 파일 찾기)
2. 복잡성별 분류:
   - 단순 (state만): ~15개 컴포넌트
   - 중간 (라이프사이클 메서드): ~23개 컴포넌트
   - 복잡 (다중 라이프사이클, refs): ~8개 컴포넌트
3. 업데이트가 필요한 서드파티 라이브러리 식별
4. 컴포넌트 의존성 그래프 생성
5. 마이그레이션 순서 계획 (리프 노드 우선)

### 2단계: 설정 및 도구 (1시간)
6. React를 v18+로 업데이트
7. hooks용 ESLint 규칙 설정
8. 변환 템플릿 생성
9. 자동화된 테스트 설정
10. 시작 전 체크포인트 생성

### 3단계: 단순 컴포넌트 마이그레이션 (4시간)
11. 단순 상태 저장 컴포넌트 변환 (15개 컴포넌트)
12. this.state를 useState로 대체
13. this.setState를 state setter로 대체
14. 변환 후 각 컴포넌트 테스트
15. 테스트 업데이트

### 4단계: 중간 컴포넌트 마이그레이션 (8시간)
16. 라이프사이클 메서드가 있는 컴포넌트 변환 (23개 컴포넌트)
17. componentDidMount를 useEffect로 대체
18. componentDidUpdate를 useEffect로 대체
19. componentWillUnmount를 useEffect 정리로 대체
20. 철저한 테스트

### 5단계: 복잡 컴포넌트 마이그레이션 (12시간)
21. 복잡 컴포넌트 변환 (8개 컴포넌트)
22. refs를 useRef로 대체
23. 공유 로직을 위한 커스텀 hooks 추출
24. 엣지 케이스 처리 (다중 useEffect)
25. 광범위한 테스트

### 6단계: 공유 로직 추출 (6시간)
26. 컴포넌트 간 중복 로직 식별
27. 커스텀 hooks 생성:
    - useAuth
    - useFetch
    - useLocalStorage
    - useDebounce
28. 커스텀 hooks를 사용하도록 컴포넌트 리팩토링
29. 커스텀 hooks 독립 테스트

### 7단계: 성능 최적화 (4시간)
30. 필요한 곳에 React.memo 추가
31. useCallback으로 최적화
32. useMemo로 최적화
33. 프로파일링 및 성능 회귀 수정

### 8단계: 정리 및 문서화 (2시간)
34. 사용하지 않는 클래스 컴포넌트 유틸리티 제거
35. 문서 업데이트
36. 코딩 가이드라인 업데이트
37. 팀을 위한 마이그레이션 가이드 생성

**예상 시간**: 5일 (39시간)
**수정할 파일**: 46개 컴포넌트
**위험 수준**: 중간

**마이그레이션 순서**:
1. 리프 컴포넌트 (의존성 없음)
2. 중간 레벨 컴포넌트
3. 최상위 컨테이너 컴포넌트
4. App.jsx (마지막)

**테스트 전략**:
- 각 컴포넌트에 대한 단위 테스트
- 사용자 흐름에 대한 통합 테스트
- 시각적 회귀 테스트
- 성능 벤치마크

**성공 지표**:
- 모든 테스트 통과
- 시각적 회귀 없음
- 성능 유지 또는 개선
- 번들 크기 크게 증가하지 않음

진행하시겠습니까? (yes/no/modify)

## 핵심 요점

### Planning Mode의 이점

1. **명확성**: 시작하기 전에 명확한 로드맵
2. **견적**: 시간 및 노력 견적
3. **위험 평가**: 잠재적 문제 조기 식별
4. **우선순위 설정**: 논리적 작업 순서
5. **승인**: 실행 전 검토 및 승인
6. **수정**: 피드백 기반 계획 조정

### Planning Mode 사용 시기

✅ **항상 사용해야 하는 경우**:
- 여러 날이 걸리는 프로젝트
- 팀 협업
- 중요한 시스템 변경
- 새로운 개념 학습
- 복잡한 리팩토링

❌ **사용하지 말아야 하는 경우**:
- 버그 수정
- 작은 조정
- 간단한 질문
- 빠른 실험
