# 체크포인트 예제

Claude Code에서 체크포인트를 효과적으로 사용하는 실제 예제입니다.

참고: 체크포인트는 모든 사용자 프롬프트마다 자동으로 생성됩니다. 수동으로 저장할 필요가 없습니다. 되감으려면 `Esc`를 두 번(`Esc+Esc`) 누르거나 `/rewind`를 사용하여 체크포인트 브라우저를 여세요.

## 예제 1: 데이터베이스 마이그레이션

### 시나리오
MySQL에서 PostgreSQL로 마이그레이션해야 하지만, 직접 마이그레이션과 점진적 이중 쓰기 접근 방식을 모두 탐색하려고 합니다.

### 워크플로우

```
User: MySQL에서 PostgreSQL로 직접 마이그레이션을 구현해 봅시다
      [체크포인트 A 자동 생성]

Claude: 직접 마이그레이션을 구현하겠습니다...
[데이터베이스 드라이버 변경, 쿼리 업데이트, 스키마 수정]

User: 테스트를 실행해 주세요
      [체크포인트 B 자동 생성]

Claude: 테스트를 실행합니다...
❌ 15개 테스트 실패 - 연결 풀 문제

User: 이 접근 방식에 문제가 있네요. 대신 이중 쓰기 패턴을 시도해 봅시다.
[사용자가 Esc+Esc를 누르고 체크포인트 A를 선택한 후 "코드와 대화 복원" 선택]

User: 이제 두 데이터베이스에 모두 쓰는 이중 쓰기 패턴을 구현해 주세요

Claude: 이중 쓰기 마이그레이션을 구현하겠습니다...
[이중 쓰기 레이어 구현, 점진적 마이그레이션 전략]

User: 테스트를 실행해 주세요

Claude: 테스트를 실행합니다...
✅ 모든 테스트 통과

User: 이중 쓰기 접근 방식이 확실히 더 안전하네요. 커밋합시다.
```

## 예제 2: 성능 최적화

### 시나리오
여러 성능 최적화 전략을 시도해야 합니다.

### 워크플로우

```
User: API 응답 시간을 최적화해 봅시다. 현재: 450ms
      [체크포인트 "Baseline" 자동 생성]

Claude: 데이터베이스 쿼리 캐싱을 추가하겠습니다...
[Redis 캐싱 구현]

User: 성능 테스트를 실행해 주세요

Claude: 결과: 평균 응답 시간 280ms (38% 개선)

User: 다른 접근 방식을 시도해 봅시다.
[사용자가 Esc+Esc를 누르고 "Baseline" 체크포인트 선택 후 "코드와 대화 복원"]

User: 데이터베이스 쿼리 최적화를 대신 시도해 주세요

Claude: 데이터베이스 쿼리를 최적화하겠습니다...
[인덱스 추가, N+1 쿼리 최적화]

User: 성능 테스트를 실행해 주세요

Claude: 결과: 평균 응답 시간 180ms (60% 개선)

User: 세 번째 접근 방식도 시도해 봅시다.
[사용자가 Esc+Esc를 누르고 "Baseline" 체크포인트 선택 후 "코드와 대화 복원"]

User: 응답 압축과 CDN을 시도해 주세요

Claude: 압축과 CDN을 추가하겠습니다...
[gzip 구현, CDN 설정]

User: 성능 테스트를 실행해 주세요

Claude: 결과: 평균 응답 시간 320ms (29% 개선)

User: 쿼리 최적화가 가장 좋았네요. 돌아가서 캐싱과 결합해 봅시다.
[사용자가 Esc+Esc를 누르고 쿼리 최적화 후 체크포인트 선택 후 "코드와 대화 복원"]

User: 이제 최적화된 쿼리 위에 Redis 캐싱을 추가해 주세요

Claude: [최적화된 쿼리 위에 Redis 캐싱 추가]

User: 성능 테스트를 실행해 주세요

Claude: 결과: 평균 응답 시간 95ms (79% 개선) 🎉

User: 완벽해요! 이걸로 결정입니다. 커밋합시다.
```

## 예제 4: 디버깅 세션

### 시나리오
여러 가설로 까다로운 버그를 추적.

### 워크플로우

```
User: 애플리케이션에 메모리 누수가 있습니다
      [체크포인트 "디버깅 전" 자동 생성]

Claude: 조사해 보겠습니다...
[코드 분석]

User: 이벤트 리스너에 문제가 있는 것 같아요. 그걸 고쳐 봅시다.

Claude: [이벤트 리스너 정리 수정]

User: 메모리 프로파일러를 실행해 주세요

Claude: 여전히 메모리 누수가 있습니다 - 이벤트 리스너가 문제가 아니었습니다

User: 돌아가서 다른 가설을 시도해 봅시다.
[사용자가 Esc+Esc를 누르고 "디버깅 전" 체크포인트 선택 후 "코드와 대화 복원"]

User: 데이터베이스 연결 문제일까요?

Claude: [연결 풀링 수정 구현]

User: 메모리 프로파일러를 실행해 주세요

Claude: 여전히 누수 - 연결 문제도 아니었습니다

User: 돌아가서 다른 각도를 시도해 봅시다.
[사용자가 Esc+Esc를 누르고 "디버깅 전" 체크포인트 선택 후 "코드와 대화 복원"]

User: 순환 참조를 확인해 봅시다

Claude: [캐시에서 순환 참조 발견 및 수정]

User: 메모리 프로파일러를 실행해 주세요

Claude: ✅ 메모리 누수 수정됨! 캐싱 레이어의 순환 참조가 원인이었습니다.

User: 훌륭합니다! 이 수정 사항을 커밋합시다.
```

## 예제 8: 체크포인트에서 요약 사용

### 시나리오
긴 디버깅 세션 후 컨텍스트를 보존하면서 대화를 압축하려고 합니다.

### 워크플로우

```
User: [20개 이상의 디버깅 및 탐색 메시지 후]

[사용자가 Esc+Esc를 누르고 초기 체크포인트를 선택한 후 "여기서부터 요약" 선택]
[선택적으로 지침 제공: "시도한 것과 작동한 것에 초점을 맞춰 주세요"]

Claude: [해당 지점부터의 대화 요약 생성]
[원본 메시지는 트랜스크립트에 보존됨]
[요약이 표시되는 대화를 대체하여 컨텍스트 창 사용량 감소]

User: 이제 작동한 접근 방식으로 계속해 봅시다.
```

## 핵심 요점

1. **체크포인트는 자동입니다**: 모든 사용자 프롬프트가 체크포인트를 생성합니다 -- 수동 저장 불필요
2. **Esc+Esc 또는 /rewind 사용**: 체크포인트 브라우저에 접근하는 두 가지 방법입니다
3. **올바른 복원 옵션 선택**: 필요에 따라 코드, 대화, 둘 다 복원하거나 요약하세요
4. **실험을 두려워하지 마세요**: 체크포인트는 급진적인 변경을 안전하게 만듭니다
5. **git과 결합**: 탐색에는 체크포인트를, 최종 작업에는 git을 사용하세요
6. **긴 세션 요약**: "여기서부터 요약"을 사용하여 대화를 관리 가능하게 유지하세요
