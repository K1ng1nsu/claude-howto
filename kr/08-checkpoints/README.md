# 체크포인트 및 되감기

체크포인트를 사용하면 대화 상태를 저장하고 Claude Code 세션에서 이전 지점으로 되감을 수 있습니다. 이는 다양한 접근 방식을 탐색하거나, 실수에서 복구하거나, 대체 솔루션을 비교하는 데 매우 유용합니다.

## 개요

체크포인트를 사용하면 대화 상태를 저장하고 이전 지점으로 되감아 안전한 실험과 여러 접근 방식 탐색이 가능합니다. 이는 대화 상태의 스냅샷으로, 다음을 포함합니다:
- 교환된 모든 메시지
- 수행된 파일 수정
- 도구 사용 기록
- 세션 컨텍스트

체크포인트는 다양한 접근 방식을 탐색하거나, 실수에서 복구하거나, 대체 솔루션을 비교할 때 매우 유용합니다.

## 핵심 개념

| 개념 | 설명 |
|------|------|
| **체크포인트** | 메시지, 파일, 컨텍스트를 포함한 대화 상태의 스냅샷 |
| **되감기** | 이전 체크포인트로 돌아가 후속 변경 사항을 폐기 |
| **분기점** | 여러 접근 방식을 탐색하는 체크포인트 |

## 체크포인트 접근

두 가지 주요 방법으로 체크포인트에 접근하고 관리할 수 있습니다:

### 키보드 단축키 사용
`Esc`를 두 번(`Esc` + `Esc`) 눌러 체크포인트 인터페이스를 열고 저장된 체크포인트를 탐색합니다.

### Slash Command 사용
`/rewind` 명령어(별칭: `/checkpoint`)를 사용하여 빠르게 접근:

```bash
# 되감기 인터페이스 열기
/rewind

# 또는 별칭 사용
/checkpoint
```

## 되감기 옵션

되감기를 실행하면 다섯 가지 옵션이 있는 메뉴가 표시됩니다:

1. **코드와 대화 복원** -- 파일과 메시지를 모두 해당 체크포인트로 되돌리기
2. **대화 복원** -- 메시지만 되감고 현재 코드는 그대로 유지
3. **코드 복원** -- 파일 변경만 되돌리고 전체 대화 기록 유지
4. **여기서부터 요약** -- 이 지점부터의 대화를 AI 생성 요약으로 압축하여 컨텍스트 창 공간 확보. 선택한 지점 이전의 메시지는 그대로 유지됨. 디스크의 파일은 변경되지 않음. 원본 메시지는 세션 트랜스크립트에 보존됨. 선택적으로 요약을 특정 주제에 집중하도록 지침을 제공할 수 있음
5. **취소** -- 취소하고 현재 상태로 돌아가기

> **참고**: 대화 복원 또는 요약 후, 선택한 메시지의 원래 프롬프트가 입력 필드에 복원되어 다시 보내거나 편집할 수 있습니다.

> **`/clear`는 더 이상 하드 경계가 아닙니다 (v2.1.191+)**: `/rewind`는 `/clear`를 실행하기 *전에* 찍은 체크포인트에서 재개할 수 있습니다. 대화를 지워도 그 이전 상태가 영구적으로 사라지지 않습니다 — 이전 코드나 컨텍스트가 필요하면 Clear를 넘어 되감을 수 있습니다.

## 자동 체크포인트

Claude Code가 자동으로 체크포인트를 생성합니다:

- **모든 사용자 프롬프트** - 각 사용자 입력마다 새 체크포인트 생성
- **지속적** - 체크포인트가 세션 간에 유지됨
- **자동 정리** - 30일 후 체크포인트가 자동으로 정리됨

이는 몇 분 전에서 며칠 전까지 대화의 모든 이전 지점으로 항상 되감을 수 있음을 의미합니다.

## 사용 사례

| 시나리오 | 워크플로우 |
|----------|-----------|
| **접근 방식 탐색** | 저장 → A 시도 → 저장 → 되감기 → B 시도 → 비교 |
| **안전한 리팩토링** | 저장 → 리팩토링 → 테스트 → 실패 시: 되감기 |
| **A/B 테스트** | 저장 → 디자인 A → 저장 → 되감기 → 디자인 B → 비교 |
| **실수 복구** | 문제 발견 → 마지막 좋은 상태로 되감기 |

## 체크포인트 사용

### 보기 및 되감기

`Esc`를 두 번 누르거나 `/rewind`를 사용하여 체크포인트 브라우저를 엽니다. 타임스탬프와 함께 모든 사용 가능한 체크포인트 목록이 표시됩니다. 아무 체크포인트를 선택하여 해당 상태로 되감습니다.

### 체크포인트 세부 정보

각 체크포인트는 다음을 표시합니다:
- 생성된 타임스탬프
- 수정된 파일
- 대화의 메시지 수
- 사용된 도구

## 실용 예제

### 예제 1: 다양한 접근 방식 탐색

```
User: API에 캐싱 레이어를 추가해 봅시다

Claude: API 엔드포인트에 Redis 캐싱을 추가하겠습니다...
[체크포인트 A에서 변경]

User: 사실 인메모리 캐싱을 대신 시도해 봅시다

Claude: 다른 접근 방식을 탐색하기 위해 되감겠습니다...
[사용자가 Esc+Esc를 누르고 체크포인트 A로 되감기]
[체크포인트 B에서 인메모리 캐싱 구현]

User: 이제 두 접근 방식을 비교할 수 있겠네요
```

### 예제 2: 실수에서 복구

```
User: 인증 모듈을 JWT로 리팩토링해 주세요

Claude: 인증 모듈을 리팩토링하겠습니다...
[광범위한 변경 수행]

User: 잠깐, OAuth 통합이 망가졌네요. 다시 돌아갑시다.

Claude: 리팩토링 전으로 되감기를 도와드리겠습니다...
[사용자가 Esc+Esc를 누르고 리팩토링 전 체크포인트 선택]

User: 이번에는 더 보수적인 접근 방식으로 해 봅시다
```

### 예제 3: 안전한 실험

```
User: 이걸 함수형 스타일로 다시 작성해 봅시다
[실험 전 체크포인트 생성]

Claude: [실험적 변경 수행]

User: 테스트가 실패하네요. 되감읍시다.
[사용자가 Esc+Esc를 누르고 체크포인트로 되감기]

Claude: 변경을 되감았습니다. 다른 접근 방식을 시도해 봅시다.
```

### 예제 4: 분기 접근 방식

```
User: 두 가지 데이터베이스 디자인을 비교하고 싶습니다
[체크포인트 기록 - "시작"이라고 부름]

Claude: 첫 번째 디자인을 만들겠습니다...
[스키마 A 구현]

User: 이제 돌아가서 두 번째 접근 방식을 시도해 봅시다
[사용자가 Esc+Esc를 누르고 "시작"으로 되감기]

Claude: 이제 스키마 B를 구현하겠습니다...
[스키마 B 구현]

User: 좋아요! 이제 선택할 수 있는 두 가지 스키마가 있네요
```

## 체크포인트 보존

Claude Code가 체크포인트를 자동으로 관리합니다:

- 모든 사용자 프롬프트마다 체크포인트가 자동 생성됨
- 오래된 체크포인트는 최대 30일간 보존됨
- 무제한 저장 공간 증가를 방지하기 위해 체크포인트가 자동으로 정리됨

## 워크플로우 패턴

### 탐색을 위한 분기 전략

여러 접근 방식을 탐색할 때:

```
1. 초기 구현으로 시작 → 체크포인트 A
2. 접근 방식 1 시도 → 체크포인트 B
3. 체크포인트 A로 되감기
4. 접근 방식 2 시도 → 체크포인트 C
5. B와 C의 결과 비교
6. 최고의 접근 방식 선택 후 계속
```

### 안전한 리팩토링 패턴

중요한 변경을 수행할 때:

```
1. 현재 상태 → 체크포인트 (자동)
2. 리팩토링 시작
3. 테스트 실행
4. 테스트 통과 → 계속 작업
5. 테스트 실패 → 되감고 다른 접근 방식 시도
```

## 모범 사례

체크포인트는 자동으로 생성되므로 수동으로 상태를 저장하는 것에 대해 걱정하지 않고 작업에 집중할 수 있습니다. 그러나 다음 사항을 염두에 두세요:

### 체크포인트 효과적으로 사용하기

✅ **권장:**
- 되감기 전에 사용 가능한 체크포인트 검토
- 다른 방향을 탐색하고 싶을 때 되감기 사용
- 다양한 접근 방식을 비교하기 위해 체크포인트 유지
- 각 되감기 옵션의 기능 이해 (코드와 대화 복원, 대화 복원, 코드 복원, 또는 요약)

❌ **금지:**
- 코드 보존을 위해 체크포인트에만 의존
- 체크포인트가 외부 파일 시스템 변경을 추적할 것으로 기대
- 체크포인트를 git 커밋의 대체 수단으로 사용

## 설정

체크포인트는 Claude Code의 내장 기본 동작이며 활성화를 위한 별도 설정이 필요하지 않습니다. 모든 사용자 프롬프트가 자동으로 체크포인트를 생성합니다.

유일한 체크포인트 관련 설정은 `cleanupPeriodDays`로, 세션 및 체크포인트 보존 기간을 제어합니다:

```json
{
  "cleanupPeriodDays": 30
}
```

- `cleanupPeriodDays`: 세션 기록 및 체크포인트 보존 일수 (기본값: `30`)

> **v2.1.117 업데이트**: `cleanupPeriodDays`는 이제 체크포인트뿐만 아니라 네 가지 온디스크 캐시의 보존을 관리합니다:
>
> - 세션 체크포인트
> - `~/.claude/tasks/` — 지속적 작업 목록
> - `~/.claude/shell-snapshots/` — 캡처된 쉘 환경 스냅샷
> - `~/.claude/backups/` — 롤링 설정 / CLAUDE.md 백업
>
> 단일 설정으로 동일한 일수 후에 네 디렉토리를 모두 균일하게 정리합니다.

## 제한 사항

체크포인트에는 다음과 같은 제한 사항이 있습니다:

- **Bash 명령어 변경 추적 안 됨** - `rm`, `mv`, `cp` 같은 파일 시스템 작업은 체크포인트에 캡처되지 않음
- **외부 변경 추적 안 됨** - Claude Code 외부(에디터, 터미널 등)에서 이루어진 변경은 캡처되지 않음
- **버전 관리 대체 아님** - 코드베이스의 영구적이고 감사 가능한 변경에는 git 사용

## 문제 해결

### 체크포인트 누락

**문제**: 예상한 체크포인트를 찾을 수 없음

**해결책**:
- 체크포인트가 지워졌는지 확인
- 디스크 공간 확인
- `cleanupPeriodDays`가 충분히 높게 설정되었는지 확인 (기본값: 30일)

### 되감기 실패

**문제**: 체크포인트로 되감을 수 없음

**해결책**:
- 커밋되지 않은 변경 사항이 충돌하지 않는지 확인
- 체크포인트가 손상되었는지 확인
- 다른 체크포인트로 되감기 시도

## Git과의 통합

체크포인트는 git을 보완하지만 대체하지는 않습니다:

| 기능 | Git | 체크포인트 |
|------|-----|-----------|
| 범위 | 파일 시스템 | 대화 + 파일 |
| 지속성 | 영구적 | 세션 기반 |
| 세분성 | 커밋 | 모든 지점 |
| 속도 | 느림 | 즉시 |
| 공유 | 가능 | 제한적 |

둘을 함께 사용:
1. 빠른 실험에는 체크포인트 사용
2. 최종 변경 사항에는 git 커밋 사용
3. git 작업 전에 체크포인트 생성
4. 성공적인 체크포인트 상태를 git에 커밋

## 빠른 시작 가이드

### 기본 워크플로우

1. **정상적으로 작업** - Claude Code가 자동으로 체크포인트 생성
2. **돌아가고 싶을 때** - `Esc`를 두 번 누르거나 `/rewind` 사용
3. **체크포인트 선택** - 목록에서 선택하여 되감기
4. **복원할 항목 선택** - 코드와 대화 복원, 대화 복원, 코드 복원, 여기서부터 요약, 또는 취소 중 선택
5. **계속 작업** - 해당 지점으로 돌아감

### 키보드 단축키

- **`Esc` + `Esc`** - 체크포인트 브라우저 열기
- **`/rewind`** - 체크포인트에 접근하는 대체 방법
- **`/checkpoint`** - `/rewind`의 별칭

## 되감기 시점 알기: 컨텍스트 모니터링

체크포인트를 사용하면 돌아갈 수 있습니다 — 하지만 *언제* 돌아가야 하는지 어떻게 알 수 있을까요? 대화가 길어질수록 Claude의 컨텍스트 창이 채워지고 모델 품질이 조용히 저하됩니다. 인식하지 못한 채 절반만 보는 모델에서 코드를 배포하고 있을 수도 있습니다.

**[cc-context-stats](https://github.com/luongnv89/cc-context-stats)** 는 Claude Code 상태 표시줄에 실시간 **컨텍스트 영역**을 추가하여 이 문제를 해결합니다. 컨텍스트 창의 위치를 **Plan**(녹색, 계획 및 코딩에 안전)부터 **Code**(노란색, 새 계획 시작 자제), **Dump**(주황색, 마무리하고 되감기)까지 추적합니다. 영역 전환이 보이면 품질이 저하된 출력을 밀어붙이지 말고 체크포인트를 만들고 새로 시작해야 할 때입니다.

## 요약

체크포인트는 Claude Code의 자동 기능으로, 작업 손실에 대한 두려움 없이 다양한 접근 방식을 안전하게 탐색할 수 있게 해줍니다. 모든 사용자 프롬프트가 자동으로 새 체크포인트를 생성하므로 세션의 모든 이전 지점으로 되감을 수 있습니다.

주요 혜택:
- 여러 접근 방식을 두려움 없이 실험
- 실수에서 빠르게 복구
- 다양한 솔루션을 나란히 비교
- 버전 관리 시스템과 안전하게 통합

기억하세요: 체크포인트는 git의 대체 수단이 아닙니다. 빠른 실험에는 체크포인트를, 영구적인 코드 변경에는 git을 사용하세요.
