# Claude How To 기여하기

이 프로젝트에 기여해 주셔서 감사합니다! 이 가이드는 효과적으로 기여하는 방법을 이해하는 데 도움을 줍니다.

## 이 프로젝트에 대해

Claude How To는 Claude Code에 대한 시각적이고 예제 중심의 가이드입니다. 다음을 제공합니다:
- **Mermaid 다이어그램**으로 기능 작동 방식 설명
- **프로덕션에 바로 사용 가능한 템플릿**
- **컨텍스트와 모범 사례가 포함된 실제 예제**
- **초급부터 고급까지 점진적 학습 경로**

## 기여 유형

### 1. 새로운 예제 또는 템플릿
기존 기능(슬래시 명령어, 스킬, 훅 등)에 대한 예제를 추가합니다:
- 복사-붙여넣기 가능한 코드
- 작동 방식에 대한 명확한 설명
- 사용 사례 및 이점
- 문제 해결 팁

### 2. 문서 개선
- 혼란스러운 섹션 명확화
- 오타 및 문법 수정
- 누락된 정보 추가
- 코드 예제 개선

### 3. 기능 가이드
새로운 Claude Code 기능에 대한 가이드를 만듭니다:
- 단계별 튜토리얼
- 아키텍처 다이어그램
- 일반적인 패턴 및 안티패턴
- 실제 워크플로우

### 4. 버그 리포트
발생한 문제를 보고합니다:
- 예상했던 동작을 설명
- 실제로 발생한 동작을 설명
- 재현 단계를 포함
- 관련 Claude Code 버전과 OS를 추가

### 5. 피드백 및 제안
가이드 개선에 도움을 줍니다:
- 더 나은 설명 제안
- 적용 범위의 공백 지적
- 새로운 섹션 또는 재구성 추천

## 시작하기

### 1. 포크 및 클론
```bash
git clone https://github.com/luongnv89/claude-howto.git
cd claude-howto
```

### 2. 브랜치 생성
설명적인 브랜치 이름을 사용하세요:
```bash
git checkout -b add/feature-name
git checkout -b fix/issue-description
git checkout -b docs/improvement-area
```

### 3. 환경 설정

Pre-commit 훅은 매 커밋 전에 CI와 동일한 검사를 로컬에서 실행합니다. PR이 승인되려면 4가지 검사가 모두 통과해야 합니다.

**필요한 의존성:**

```bash
# Python 도구 (uv는 이 프로젝트의 패키지 관리자입니다)
pip install uv
uv venv
source .venv/bin/activate
uv pip install -r scripts/requirements-dev.txt

# Markdown 린터 (Node.js)
npm install -g markdownlint-cli

# Mermaid 다이어그램 검증기 (Node.js)
npm install -g @mermaid-js/mermaid-cli

# Pre-commit 설치 및 훅 활성화
uv pip install pre-commit
pre-commit install
```

**설정 확인:**

```bash
pre-commit run --all-files
```

매 커밋마다 실행되는 훅은 다음과 같습니다:

| 훅 | 검사 내용 |
|------|---------------|
| `markdown-lint` | 마크다운 형식 및 구조 |
| `cross-references` | 상대 링크, 앵커, 코드 펜스 |
| `mermaid-syntax` | 모든 ` ```mermaid ` 블록이 올바르게 파싱되는지 확인 |
| `link-check` | 외부 URL에 접근 가능한지 확인 |
| `build-epub` | EPUB이 오류 없이 생성되는지 확인 (`.md` 변경 시) |

## 예제 기여 방법

### 슬래시 명령어 추가
1. `01-slash-commands/`에 `.md` 파일을 만듭니다
2. 다음을 포함합니다:
   - 기능에 대한 명확한 설명
   - 사용 사례
   - 설치 방법
   - 사용 예제
   - 커스터마이징 팁
3. `01-slash-commands/README.md`를 업데이트합니다

### 스킬 추가
1. `03-skills/`에 디렉토리를 만듭니다
2. 다음을 포함합니다:
   - `SKILL.md` - 주요 문서
   - `scripts/` - 필요한 경우 헬퍼 스크립트
   - `templates/` - 프롬프트 템플릿
   - README에 사용 예제
3. `03-skills/README.md`를 업데이트합니다

### 서브에이전트 추가
1. `04-subagents/`에 `.md` 파일을 만듭니다
2. 다음을 포함합니다:
   - 에이전트 목적 및 기능
   - 시스템 프롬프트 구조
   - 사용 예제
   - 통합 예제
3. `04-subagents/README.md`를 업데이트합니다

### MCP 설정 추가
1. `05-mcp/`에 `.json` 파일을 만듭니다
2. 다음을 포함합니다:
   - 설정 설명
   - 필요한 환경 변수
   - 설정 방법
   - 사용 예제
3. `05-mcp/README.md`를 업데이트합니다

### 훅 추가
1. `06-hooks/`에 `.sh` 파일을 만듭니다
2. 다음을 포함합니다:
   - Shebang 및 설명
   - 로직을 설명하는 명확한 주석
   - 오류 처리
   - 보안 고려 사항
3. `06-hooks/README.md`를 업데이트합니다

## 작성 가이드라인

### 마크다운 스타일
- 명확한 제목 사용 (H2는 섹션, H3는 하위 섹션)
- 단락을 짧고 집중적으로 유지
- 목록에는 불릿 포인트 사용
- 언어 지정과 함께 코드 블록 포함
- 섹션 사이에 빈 줄 추가

### 코드 예제
- 복사-붙여넣기가 가능하도록 준비
- 명확하지 않은 로직에는 주석 작성
- 간단한 버전과 고급 버전 모두 포함
- 실제 사용 사례 제시
- 잠재적 문제 강조

### 문서
- "무엇"뿐만 아니라 "왜"를 설명
- 전제 조건 포함
- 문제 해결 섹션 추가
- 관련 주제로 링크
- 초보자에게 친숙하게 유지

### JSON/YAML
- 적절한 들여쓰기 사용 (일관되게 2 또는 4칸)
- 설정을 설명하는 주석 추가
- 검증 예제 포함

### 다이어그램
- 가능하면 Mermaid 사용
- 다이어그램을 간단하고 읽기 쉽게 유지
- 다이어그램 아래에 설명 포함
- 관련 섹션으로 링크

## 커밋 가이드라인

기존 커밋 형식을 따르세요:
```
type(scope): description

[optional body]
```

유형:
- `feat`: 새로운 기능 또는 예제
- `fix`: 버그 수정 또는 정정
- `docs`: 문서 변경
- `refactor`: 코드 구조 변경
- `style`: 형식 변경
- `test`: 테스트 추가 또는 변경
- `chore`: 빌드, 의존성 등

예제:
```
feat(slash-commands): Add API documentation generator
docs(memory): Improve personal preferences example
fix(README): Correct table of contents link
docs(skills): Add comprehensive code review skill
```

- [ ] 링크가 확인되고 올바릅니다
- [ ] 파일에 적절한 권한이 설정되어 있습니다 (스크립트는 실행 가능)

## 풀 리퀘스트 절차

1. **명확한 설명과 함께 PR 생성**:
   - 무엇을 추가/수정하나요?
   - 왜 필요한가요?
   - 관련 이슈 (있는 경우)

2. **관련 세부 정보 포함**:
   - 새로운 기능? 사용 사례 포함
   - 문서? 개선 사항 설명
   - 예제? 전후 비교 표시

3. **이슈 연결**:
   - `Closes #123`을 사용하여 관련 이슈 자동 종료

4. **리뷰에 인내심을 가지세요**:
   - 관리자가 개선 사항을 제안할 수 있습니다
   - 피드백에 따라 반복 개선합니다
   - 최종 결정은 관리자에게 있습니다

## 프로젝트 정책

### 민감한 정보
- API 키, 토큰 또는 자격 증명을 절대 커밋하지 않음
- 예제에 플레이스홀더 값 사용
- 설정 파일에 `.env.example` 포함
- 필요한 환경 변수 문서화

### 코드 품질
- 예제를 집중적이고 읽기 쉽게 유지
- 과도한 엔지니어링 방지
- 명확하지 않은 로직에 주석 포함
- 제출 전 철저히 테스트

### 지적 재산권
- 원본 콘텐츠는 작성자 소유
- 프로젝트는 교육용 라이선스 사용
- 기존 저작권 존중
- 필요한 경우 출처 표시
